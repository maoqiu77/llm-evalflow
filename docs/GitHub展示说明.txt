GitHub 展示说明
================

一、为什么需要静态快照
GitHub 只能直接展示静态网页，不能自动运行你的 FastAPI 后端。
所以本项目采用“双模式”：

1. 本地动态模式
启动 FastAPI + React，支持新增问题、调用模型、自动评分、Badcase 归因。
数据保存在 backend/llm_evalflow.db，电脑重启后不会丢。

2. GitHub 静态展示模式
把已完成的评测结果导出为 frontend/public/demo-data.json。
当前端访问不到后端 API 时，会自动读取这个 JSON 文件，展示固定的评测结果。

二、导出方式
本地启动项目后，点击左侧“导出 GitHub 展示”按钮。
系统会生成：

frontend/public/demo-data.json
docs/evaluation_report.md

三、上传 GitHub 前建议保留的文件
建议保留：
- backend/
- frontend/
- docs/
- sample_data/
- README.md
- start.sh
- 启动项目.command
- start_backend.ps1
- start_frontend.ps1

不要上传：
- backend/.env
- backend/llm_evalflow.db
- frontend/node_modules/
- frontend/dist/（除非你准备用 dist 直接部署 Pages）

四、GitHub Pages 建议
你的 GitHub 主页是：
https://github.com/maoqiu77

建议仓库名：
llm-evalflow

Pages 展示方式：
1. 推荐：使用 GitHub Actions 从 frontend 自动构建。
2. 简单：本地 npm run build 后，把 frontend/dist 发布到 Pages 分支。

五、展示效果
如果后端不存在，前端会显示“静态快照”提示，并从 demo-data.json 展示：
- Dashboard 总览
- 模型横向对比
- Badcase 统计
- 评测报告

静态模式不能新增问题或重新调用模型；这些操作需要在本地动态模式完成后再次导出快照。
